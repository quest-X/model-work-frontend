# Frontend 主线收束

更新日期：2026-11-04。

## 范围与构建

Git `main` 是统一开发主线；`master` 的功能合入同一代码。Git 分支名不代表设备 Main/Master/Node 的权限，设备权限仍由现有 Node/Backend 接口校验。本轮不实现 LAW，也不改变已有签名、审批或密钥。

- 通用：`npm run dev` / `npm run build`，默认显示完整通用入口，包括 OTA 管理；已有引擎健康与节点能力检测仍生效。
- 山钢日照：`VITE_OPENSIGHT_SHANGANG_RIZHAO_COMMERCIAL=1 npm run build`，保留客户工具、地图与 OTA 展示限制。`scripts/deploy-shangang-frontend.sh` 显式设置此变量，不能依赖分支名推断构建类型。
- 展示限制不是授权边界；前端按钮可见也不能代替后端授权。远程平台入口仅在本机地址、Main 角色且声明平台能力时出现，票据和地址校验保留。

## 合并取舍

保留 main 的完整电文历史、慢预览请求保护、PDF/Excel/原始 CSV 导出、节点实际角色/归属、作业区与相机展示、独立轮询。统计导出分支的两次提交已被 main 的增强版覆盖，保留较新实现并接入其历史。

补入 master 的边缘设备程序运行器、子平台入口、设备类型筛选、过滤后图谱自适应布局、群查询独立加载、地图与 CI 修复。节点排序与类型筛选共存。使用 main 的真实角色层级布局，旧版固定顺时针坐标测试由现有归属链测试替代。通用构建恢复 OTA 面板，商用构建保持隐藏。

验证包含全量 Jest、类型、lint、两种生产构建及 Chrome 固定接口验收。固定接口可证明前端交互与接口契约，不能证明现场 OTA 执行、真实相机画面或跨仓服务部署验收。

## 后续维护

功能改动提交到 main；客户差异通过明确配置和原有产品边界保留。完成祖先关系核对后停止在旧 master 继续开发；保留带未提交内容的历史 worktree，逐项报告，不自动覆盖或删除。Node、Extension 的收束由各自负责人完成，使用固定 SHA 组合再进行跨仓联调。LAW 见共享仓库 `docs/LAW_LONG_TERM_PLAN.md`，未来单独启动。
